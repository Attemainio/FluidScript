## Blocking findings

### F-1 · `nodes=4` has two cardinalities with no hydraulic/thermal mapping

**Evidence.** `22-component-model.md:254-257` defines `nodes=n` as **n internal nodes and n+1
segments**; `23-topology-and-graph.md:169-171` repeats that lowering as n+1 equal-length sub-pipes.
The demand-step reference instead calls the same `PB ... nodes=4` four 2 m segments
(`01-vision-and-scope.md:457,482-483`) and assigns one 2 m control volume to each of four thermal lags
(`01:510-515`; `33-transient-time-domain.md:293-335`). Those shapes can coexist only if the contract
explicitly distinguishes four thermal cells from five hydraulic sub-pipes and assigns the pipe's
volume separately from its pressure-drop lengths; no document does. The topology acceptance criterion
says five graph nodes and five sub-pipes (`23:526`), while the layout criterion calls the resulting
group five components (`25:276`), although the expanded graph contains four internal nodes plus five
sub-pipes. Finally,
`57-state-visualization.md:301-305` puts the transient on the wrong pipe (`P1`) and claims one segment
per 12 s, directly contradicting the named reference's `PB` path.

**Why it blocks.** A reasonable implementation can attach storage to n internal nodes, to n+1
sub-pipes, or use endpoint half-cells; each gives different state counts, per-cell volume, CFL limits,
response fixtures and group membership. The current tests simultaneously name four, five, and nine
objects without defining which surface counts which.

**Concrete correction.** Preserve that `nodes` counts internal thermodynamic nodes, then explicitly
define whether the intended model is n thermal cells of volume V/n plus n+1 hydraulic sub-pipes of
length L/(n+1) (which preserves the current four-stage/9.6 s fixture), including what `nodes=0` means.
Alternatively choose one shared n+1-cell discretization and recompute all transient/controller values.
Define whether `ComponentGroup` contains all expanded graph children or retains a separate logical-pipe
identity. Correct `57` to use `PB`, not `P1`, and replace its unsupported 12 s claim. Blast radius: `01`, `05`, `22`, `23`, `25`,
`26`, `33`, `34`, `43`, `53`, `57`, `61`, `62`, and the future sample/golden fixtures.

### F-2 · canvas overlap is both forbidden and required as fallback

**Evidence.** `53-canvas-renderer.md:179-184` requires that no symbols overlap after layout. Its error
contract at `53:190-195` requires the renderer to place with overlap when avoidance fails.

**Why it blocks.** The layout algorithm and its oracle have mutually exclusive required outcomes for
the same input, including supported 200-component scenes.

**Concrete correction.** Make non-overlap conditional on the supported post-collapse envelope and
require deterministic expansion/reflow inside it; define overlap as an explicitly degraded result
outside it. Alternatively weaken the invariant and require a visible diagnostic. Align `05`, `07`,
`53`, and `62` with the selected policy.

### F-3 · omitted parameters resolve to both sizing and defaults

**Evidence.** Root requirement `R-02` says every omitted parameter means "size this" at
`01-vision-and-scope.md:57-59`. `D-32` instead makes omitted tank volume, layer count and elevations
visible defaults (`06-decision-log.md:1068-1072`). The component prose acknowledges the exception
(`22-component-model.md:130-132`), but the public `IComponent.StatedParameters` contract still says
absence means auto-size (`22:50-58`). The future always-loaded guidance repeats the unconditional rule
(`64-claude-md-plan.md:112-114`), as does current `CLAUDE.md:96-98`.

**Why it blocks.** An implementer following the root requirement/interface sends missing tank fields
through sizing; one following the binding decision resolves defaults before sizing. That changes
provenance (`sized` versus `default`), UI styling, wire output and write-back behavior.

**Concrete correction.** Amend `R-02` and the invariant to say omission selects the kind registry's
declared resolution policy: normally sizing, but a documented explicit default where a binding
decision provides one; stated values always remain constraints. Make the interface describe only
`StatedParameters`, not infer resolution from absence, and propagate the wording to `05`, `22`, `24`,
`26`, `52`, `53`, `61`, `64`, and `CLAUDE.md`.

### F-4 · M3's symbol inventory requires M4 kinds

**Evidence.** `53-canvas-renderer.md:137-150` calls its table “the M3 acceptance inventory” and includes
`tank` and `controller`. The phase boundary schedules both for M4 (`01-vision-and-scope.md:147-153`),
and M3 explicitly says later component milestones add their symbols before those milestones exit
(`05-milestones-and-acceptance.md:158-176`).

**Why it blocks.** M3 can either obey its phase boundary and fail the renderer inventory, or implement
M4 public kinds early and violate the risk-separated slice. The milestone gate is not unambiguous.

**Concrete correction.** Mark every symbol row with its delivery milestone. Make the M3 inventory end
at the component kinds delivered through M2b; make `tank` and `controller` M4 criteria. No architecture
change is needed.

## Should-fix findings

### F-5 · thermal-stage derivation stops short of an implementable algorithm

`25-layout-hints.md:126-142` says to collapse each “hydraulic loop/group,” infer roles from duties and
terminal temperatures, and tie-break by nominal direction/source order. It does not define the unit
being staged (component, flow group, branch, loop, or connected hydraulic component), how heat-transfer
edges and transport edges combine, or how stage rank is calculated when one hydraulic component
contains multiple duties/storage elements. The storage-header golden case is precise, but general
`R-44` still requires a reasonable guess.

Define the thermal staging graph and ranking operation normatively, including cycles and neutral
components. Add substation, cooling-loop, storage-header, and one multi-conversion fixture. Blast
radius: `25`, `26`, `53`, `59`, and `62`.

### F-6 · accepted-decision citation mapping fails its own gate

`06-decision-log.md:1133-1152` requires every constrained document to cite the decision id. Mapping
each active decision's linked `Constrains` targets found **47 missing citation edges**, including all
eight linked `D-32` targets in `05`, `17`, `25`, `42`, `43`, `52`, `53`, and `62`; representative older
gaps include `D-20` in `22`/`25`/`26`/`71` and `D-27` in `18`/`52`/`58`. Much of the contract text is
present, so this is not 47 missing features, but the rationale/authority chain cannot pass its own
acceptance test.

Add the ids at the actual normative clauses, then automate this reverse check in `check.py`. Do not
add a citation only in frontmatter or a generic references paragraph.

### F-7 · the traceability root points at the wrong requirements

In the target-user table, LLM-navigation cites canvas/hover requirements `R-22` and `R-23`, while the
owned requirements are documentation `R-28`/`R-29` (`01-vision-and-scope.md:41-49`). Reviewer export
cites write-back `R-25`; static export is `R-31`. These references send a fresh implementer to the
wrong acceptance surfaces. Correct the three ids; no behavioral change is required.

### F-8 · glossary bans terms the active contract requires or still uses

The glossary bans “pipe segment,” “pressure loss,” and “channel gap” and requires their absence from
all plan documents (`02-glossary.md:153-164,187-193`). Active normative text nevertheless uses those
terms in `01:105`, `07:68`, `22:309,384`, `33:69,309`, and `57:18,164`. For transient discretization,
“branch” and “pipe” are not adequate replacements for an individual finite-volume cell, so the ban is
also missing a necessary canonical concept.

Adopt one term such as **sub-pipe** or **pipe cell** for the n+1 discretized elements, add it to the
glossary, and replace behavioral uses. Keep synonyms only in explicitly explanatory/historical text.

## Essential capabilities and non-functional contracts

The earlier remediation successfully supplies the major operational prerequisites: local durable
files and recovery, source/catalogue compatibility and migration, supported scale/input limits,
determinism, worker isolation and stop behavior, accessibility, validation data ownership, security
limits, and static export. No new subsystem is missing.

The remaining essential precision is:

1. one authoritative pipe-discretization cardinality and fixture;
2. one supported/degraded canvas-overlap policy;
3. one registry-level omission-resolution contract; and
4. a deterministic general thermal-stage derivation.
