### 10-language

**F-4 · 11-language-overview · traceability.** 11's own worked inference-count example has I2 and I3
swapped ("at least 2 from I2, 1 from I3") against the canonical count `D-11` binds the whole tree to
(3/1/2, stated correctly in 01). Fix: correct to "1 inferred from I2, 2 boundary nodes from I3."

**F-5 · 12-grammar · consistency (confirmed independently by two reviewers).** The `catalog` directive's
EBNF (`"catalog", identifier, "@", catalog-version` — one id, mandatory version) contradicts 12's own
prose/AST/examples (`catalog steel_en10255` no version; `catalog copper_en1057 steel_en10255` a
two-name unversioned preference list) and 18-script-compatibility's Contracts section, which assumes
yet a third reading (single id, mandatory version, no list). Fix: pick one shape — likely a non-empty
name list with an optional trailing `@version` — and correct the EBNF, the AST (`CatalogDirectiveSyntax`),
and 18's Contracts section to agree.

**F-6 · 13-type-and-unit-system · contract precision.** `FS1302`'s suggested fix for
"cannot add two temperatures" tells the user to write `{a} + {n} K` — which, per 13's own rule two
paragraphs earlier, is itself a `TemperatureDelta` type error (`K` is absolute, `dK` is the delta unit).
16-diagnostics reproduces the same wrong suggestion. Fix: `{a} + {n} dK` in both documents.

**F-7 · 13-type-and-unit-system · consistency.** `D-26`'s explicit gauge spellings `kPag`/`barg` are
absent from 13's unit-symbol table entirely, though `D-26` names 13 as constrained and the glossary
lists them as accepted. Fix: add `kPag`, `barg` to the Pressure row and the dimension-table note.

**F-8 · 17-formatting-and-round-trip · contract precision.** `IScriptEditor.AddConnection`/`RemoveConnection`
take an `Endpoint` type defined nowhere in `plan/`. Fix: add a `record struct Endpoint(string Component,
string? Port)`.

**F-9 · 18-script-compatibility · contract precision.** `ApplyMigration(MigrationId id)` has no stated
source for `MigrationId` — `PreviewMigration`'s return type `MigrationPreview` is documented only as a
prose field list with no `MigrationId` field at all. The one call sequence the whole migration UX
depends on is unimplementable as written. Fix: give `CompatibilityResult`/`MigrationPreview` full record
signatures including where `MigrationId` comes from.

**F-10 · 18-script-compatibility · consistency.** Same catalog-directive contradiction as F-5, approached

**F-11 · 14-expressions-and-references · contract precision.** `IDependencyGraph`'s `ValueId` and
`DeferredExpression` — central to the whole two-phase fixed-point evaluation mechanism and to
`FS1402`'s cycle-report formatting — are used throughout but never defined. Fix: add discriminated
`ValueId` (let-name / component-parameter / component-property) and a `DeferredExpression` record

**F-12 · 15-semantic-model · contract precision.** `ConnectionSymbol`, `CircuitSymbol`, `BindingSymbol`,

### 30-solver

**F-15 · 34-controllers · consistency / feasibility.** The boxed PID formula computes the derivative
term from the error (`Kd·(eₖ−2eₖ₋₁+eₖ₋₂)/dt`), but the prose two lines below requires derivative-on-
*measurement* to avoid a setpoint-step kick — these are literally different computations whenever the
setpoint changes, and the boxed formula, followed literally, produces exactly the kick invariant 6
forbids. Fix: rewrite the boxed term in terms of `measured`, not `e`.

**F-16 · 34-controllers · testability.** The worked example negates `Kp` for reverse-acting
(`−0.0275`) but computes `Ki` from the unsigned value, leaving `Ki` positive when the document's own
rule (`Ki = Kp/2τ`) demands it also be negative — a controller built from this fixture has proportional
and integral action fighting each other and will not converge as the response-shape table claims. Fix:
`Ki = −2.42×10⁻⁴`.

**F-17 · 35-evolutionary-sizing · contract precision.** `OptimizationProblem`, the one public method's

field — and `OptimizationResult.BestObjective`/`BaselineObjective` carry no stated unit (which varies by
objective: kWh, currency, kPa). Fix: add a full `OptimizationProblem` record and state each objective's
canonical unit.

**F-18 · 31-solver-architecture · consistency.** 31's worked example states the M2-demo scaled residual
norm at the sizing seed as `4.1e-1`; 36-numerics-and-convergence computes the identical quantity, same
scaling factors, as `4.2e-2` — an order of magnitude apart for the same case. Fix: recompute the true
system-wide `‖F‖∞` once and cite it from both documents (or state 36's number is a partial/illustrative
subset, not the full residual).

**F-19 · 31-solver-architecture · completeness / contract precision.** `UnknownDeclaration`,
`EquationDeclaration`, `StateVector`, `ScalingVector`, and `ResidualReport` — the types the document's
own "unknown and equation registry" ownership claim is built on, and consumed by diagnostics formatting
and the frontend — have no signatures anywhere. Fix: add a `Contracts` subsection with real record
shapes.

or explicitly scope the AA invariant to exclude dimmed/decorative syntax sub-roles with a stated floor.
