## Blocking findings

### F-1 · The sixth reference circuit has no normative definition

**Evidence.** D-33 says it adds a sixth `distribution header` reference circuit
(`06-decision-log.md:1162-1164`), while `01-vision-and-scope.md:212-230` still says five and lists only
those five. M2a and M3 nevertheless gate on the distribution header (`05:142-150`, `05:213-219`), and
`25`/`53` restate partial variants.

**Why it blocks.** There is no authoritative script, attachment inventory, node/component inventory,
solved state, or sample filename. The exact drift D-11 prohibits has already begun: downstream
documents invent the fixture independently.

**Correction.** Define `samples/m2-distribution-header.fluid` in `01` with a complete script and
expected values, add it to the reference table and M2a demos, then make `25`, `53`, and `62` cite it
without restating mutable details.

### F-2 · Circuit-local component names cannot be represented by the flat contracts

**Evidence.** `15-semantic-model.md:653-655` explicitly permits two circuits to each declare `PU1`.
Yet `LayoutHints.Order`, `Rank`, `Loops`, `Inferred`, and especially
`CircuitOf: ImmutableDictionary<string,string>` use bare strings (`25:65-130`). The wire contract
likewise emits bare ids in connections and every layout collection (`26:134-152`), even while its own
invariant says ids are unique only within a circuit (`26:321-324`). Diagnostics, frame-state keys,
pressure datums, SVG ids, and `IScriptEditor` methods also carry bare component strings.

**Why it blocks.** The protected distribution-header example contains two `PU1`s. One overwrites the
other in `CircuitOf`/`Rank`, a connection or frame delta cannot identify which one it addresses, and
`SetParameter("PU1", ...)` cannot select a declaration. `component.circuit` cannot qualify a reference
that has already collided as a dictionary key.

**Correction.** Introduce one stable qualified `ComponentId` (for example `{ circuit, name }`) and use
it in every cross-circuit key/reference, including layout, connections, ports, diagnostics, frame
deltas, editor calls, and export ids. Alternatively require globally unique source names, but that
would supersede the explicit D-33 contract and its two-`PU1` fixture. Also require circuit names to be
unique (with a diagnostic), since `ParentCircuit` and `component.circuit` use them as identities but no
current invariant does.

### F-3 · Subcircuit attachment does not identify its parent unambiguously

**Evidence.** `AttachmentSymbol` stores only `ParentComponentName` (`15:364-370`), and binding searches
all *other* circuits (`15:584-585`). The same document permits duplicate component names across those
circuits (`15:653-655`). The source form is only `supply N3` / `return N5` (`12:328-343`).

**Why it blocks.** If two other circuits each contain `N3`, the binder has two valid targets and the
language provides neither a parent qualifier nor an ambiguity diagnostic. Supply and return can also
resolve to different parent circuits even though the model exposes one `ParentCircuit`.

**Correction.** Make the parent explicit (for example a parent declaration or a circuit-qualified
attachment endpoint), or establish and enforce a global uniqueness rule for attachment anchors. Add
an ambiguity diagnostic and require supply/return to resolve to the same parent.

### F-4 · D-40's controller syntax does not form one compilable contract

**Evidence.** The canonical demand-step circuit still uses the superseded one-line declaration
(`01:452-465`), while D-40 requires a definition plus `control` binding (`06:1452-1466`). Grammar says
`pid`, `pi`, and `p` resolve (`12:377-393`), but the exhaustive registry contains only `pi` and instead
retains `control` (`15:226-242`); `control` is now reserved and therefore cannot appear in kind-name
position (`12:153-165`). The D-40/M1 examples use `actuate=TV1`, while `ControlBindingSymbol.Actuator`
requires a `ParameterReference` such as `TV1.position` (`15:391-400`). Finally, `IController` still
owns Measurement/Actuator/Setpoint while `ControlBindingSymbol` now owns the same values, with no
specified lowering rule between them (`34:46-77`, `15:385-405`).

**Why it blocks.** The M1 gate's `PID1 pid` scores below D-15's similarity threshold and binds as an
unknown kind; the reference M4 script tests the old model; examples disagree on whether actuator
shorthand exists; and Core has two authorities for the binding values.

**Correction.** Pick one canonical controller kind/algorithm representation; align the complete alias
table (removing the now-unwriteable `control` alias), update the demand-step reference script, use
qualified actuator parameters everywhere or define shorthand explicitly, and state how lowering turns
a `ControlBindingSymbol` into an independently stateful `IController` instance. Add cardinality rules
for reusing one definition in multiple bindings.

### F-5 · `spacing` cannot both reach the renderer and leave the model contract unchanged

**Evidence.** D-37 says spacing belongs in `StyleSettings` and crosses Core untouched
(`06:1330-1354`). The semantic model instead stores it in `ProjectSettings` (`15:312-320`,
`15:377-383`, `15:555-560`). The model-contract example contains it in neither `project` nor `style`
(`26:65-68`, `26:155`). Yet `53:146-157` says the renderer reads it from style settings and that the
entire model contract must be byte-identical for two different spacing values; V22 repeats that
impossible assertion.

**Why it blocks.** If the contract is byte-identical, the frontend cannot observe the requested
spacing. If spacing is serialized, the byte-identical test must fail. The current storage location also
contradicts the accepted decision.

**Correction.** Put spacing in the serialized style/presentation payload and change V22/M3/53 to
assert that physics, solved state, and `LayoutHints` are identical while only `style.spacing` differs.

### F-6 · `ApplyTags` rejects the reapplication scenario it explicitly promises

**Evidence.** `17-formatting-and-round-trip.md:123-126` says applying tags, inserting a pump, and
applying again renames later pumps. Lines 128-130 require the whole operation to fail whenever any
target tag already names another component.

**Why it blocks.** Start with pumps renamed `100PU01`, `100PU02`, insert a pump between them, then
reapply. The new pump targets `100PU02`, which still names the old second pump, so the required
precondition aborts the exact workflow the preceding paragraph promises.

**Correction.** Treat the rename set atomically: identifiers occupied by another member of the same
rename set are legal; fail only when a target is occupied outside the set. Specify cycle/chain handling
(temporary ids or simultaneous text replacement), add an error code, and test insertion at the start
and middle of a tagged sequence.

### F-7 · The tab requirement says detached runs both do and do not stream

**Evidence.** R-50 says only the active document “renders and streams frames” (`01:113-114`), and D-39
repeats that only the active document streams (`06:1420-1426`). The realtime authority requires the
opposite: a detached socket continues delivering every frame, and its worker continues decoding,
applying, validating, and checkpointing them (`43:135-167`, invariants `43:214-217`).

**Why it blocks.** Following the foundation requirement closes or stops draining the background
stream; following `43` keeps it open. With delta frames, the former makes resume impossible without a
fresh base—the precise failure `43` is designed to prevent.

**Correction.** Change R-50/D-39/glossary wording to “only the active document performs presentation
work”; state explicitly that detached runs keep receiving and reconstructing frames but skip colour,
geometry, and DOM work.

## Should-fix findings

### F-8 · The documentation gate's declared enumeration cannot pass

`63:65-69` now requires a page for every reserved word that introduces a statement, but the
authoritative tree (`61:75-98`) has no pages for `fluidscript`, `catalog`, `connections`, or `schedule`.
It also gives no page to R-51's user-visible solver status, and `61` does not trace R-51
(`61:1-9`). Add the missing pages (or an explicit keyword-to-combined-page manifest) and plan solver
status coverage; otherwise the non-negotiable docs gate fails by construction.

### F-9 · Closing a document has contradictory run behavior

`58:76-78` and invariant 8 (`58:137-138`) say closing the document ends its run, while FILE009 offers
“Stop/Keep for the run” (`58:152-154`). Define whether Keep cancels the close or creates a detached job;
the latter contradicts `58:118` and the v1 no-detached-server-jobs boundary.

### F-10 · Distribution-group cardinality is not a Core invariant

`25:135-142` says a renderer draws groups of two or more, but `DistributionGroup` accepts any member
count and the invariants do not require `Members.Length >= 2`. State that Core omits one-member groups
and require at least two members, matching `53`'s mode-selection rule.

### F-11 · Attachment diagnostics overlap

An attachment to the current circuit satisfies both FS1518 (“no other circuit declares it,”
`15:710`) and FS2217 (“endpoint is in the same circuit,” `23:482`). Define precedence so one source
mistake yields one diagnostic, consistent with the global one-diagnostic-per-problem rule.
