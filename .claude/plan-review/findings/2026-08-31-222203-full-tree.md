### F-1 · 01-vision-and-scope · completeness / consistency (D-11)
**Finding.** `D-33` declares a sixth reference circuit, the distribution header, and five documents now
depend on it — `05` (M2a and M3 exit criteria), `25` (worked example and three acceptance criteria),
`53` (header-layout section and two criteria), `62` (V18). It is **defined nowhere.** `01`'s reference
table still holds five rows and its prose still reads "Five are needed because they answer different
questions."
**Why it blocks.** `D-11` binds every reference circuit to be defined in `01` and makes an unnamed
variant a review finding, precisely because "the corrected cooling loop" once meant three different
circuits across six documents. That drift has already started: `25`'s worked example invents node names
`N3`/`N5` for circuit 101 and `N4`/`N6` for 102, and `53` draws a diagram with neither. No script, no
node inventory, no solved figures, and two documents already disagreeing about what the fixture is.
**Suggested fix.** Add the sixth row and a `#### The distribution header` subsection to `01` with the
full script, node names, and design-point figures, in the form the other five use; update "Five are
needed" to six with its own sentence on what it uniquely exercises (several circuits, attachment,
header layout, per-circuit tag ordinals). Then make `25` and `53` cite it rather than restate it.

### F-2 · 15-semantic-model, 25-layout-hints, 26-model-contract, 17-formatting-and-round-trip · contract precision
**Finding.** Component identity is **not circuit-qualified in any type**, although `15`'s invariant 2
now makes a name unique only *within* a circuit. Three surfaces key by a bare name:
`LayoutHints.Order`/`Rank`/`Inferred`/`CircuitOf`/`ComponentGroup.Children` (`ImmutableArray<string>`,
`ImmutableDictionary<string, int>`), `26`'s `component.id`, and `IScriptEditor`'s `string component`
parameters on `SetParameter`, `RemoveParameter`, `AddComponent` and `Rename`.
**Why it blocks.** The distribution header has two components named `PU1`, in circuits 101 and 102.
`Rank["PU1"]` can hold one of them. `25`'s own text says a renderer keying a dictionary by bare name
"would silently collapse the two" — and `LayoutHints` is exactly such a dictionary, so Core commits the
error the document warns the renderer against. `SetParameter("PU1", …)` edits an unspecified one of two
declarations. Every one of these is silent.
**Suggested fix.** Choose one and apply it everywhere: either (a) ids are globally unique, qualified at
construction as `circuit.name` (`AHU.PU1`), which keeps every existing flat structure and changes what
`Name` means, or (b) a `ComponentId` record struct `(string Circuit, string Name)` replaces `string` in
every keyed structure and every editor signature. (a) is cheaper and matches how `I2` already derives
`HE1__3WV`; (b) is more explicit. Either way `25`'s stable-id section, `26`'s invariant 3 and `17`'s
signatures must agree, and `CircuitOf` becomes redundant under (a).

### F-3 · 34-controllers · consistency (D-40)
**Finding.** `IController` still declares `Measurement`, `Actuator` and `Setpoint` as properties of the
controller, while `D-40` and the new `ControlBindingSymbol` put all three on the `control` binding.
**Why it blocks.** Two owners for one fact, with no stated direction of flow. A fresh session cannot
tell whether the controller component carries them (making the binding redundant), or the binding does
(making the interface stale), or whether lowering copies binding values onto the controller. The third
is probably intended and is written down nowhere.
**Suggested fix.** State that lowering projects a `ControlBindingSymbol` onto the `IController` instance
it names, and that the interface's three properties are populated from the binding and are read-only
consequences of it. Add it to `34`'s "The model" section and note it in `15`'s lowering boundary.

### F-4 · 18-script-compatibility · completeness / scope discipline
**Finding.** `D-33`, `D-37` and `D-40` added five reserved words — `project`, `spacing`, `supply`,
`return`, `control`. `18`'s breaking-change list ("removing syntax, changing bare-unit meaning, renaming
a kind/parameter without an alias, changing inference semantics") does not mention reserved-word
additions, and `12` justifies the additions with "None collides with an identifier in any sample or
reference circuit."
**Why it blocks.** A `fluidscript 1` script that named a component `control` or `supply` parsed before
and now fails with `FS1004`. Checking *our* samples is evidence about this repository, not about user
files, and `18` is the document that decides whether that needs a major bump and a migration. It is
currently silent, so the question is open while the change is already applied.
**Suggested fix.** Add reserved-word additions to `18`'s breaking-change list explicitly, and state the
pre-release exemption the tank paragraph already relies on: before a v1 file can be saved, the reserved
list may grow; afterwards, growing it requires a new major and a migration that renames colliding
identifiers. Correct `12`'s justification to cite that exemption rather than the sample sweep.

## 🟡 Should fix (4)

### F-5 · 25-layout-hints, 53-canvas-renderer · contract precision (D-38)
`DistributionGroup` states no minimum member count, while `25`'s remarks say "a group of two or more"
and `53` selects header mode on "2+ members". What Core emits for a parent with exactly one subcircuit
is undefined — a one-member group the renderer must silently ignore, or no group at all.
**Fix.** Add an invariant: `Members.Length >= 2`; a parent with one subcircuit produces no group and
renders as a loop rectangle. Then `53`'s "2+" test becomes a consequence rather than a second rule.

### Layout corrections from the user

- **Header branches are U-shaped, not stacked boxes.** `53`'s header section rewritten around the
  supplied shapes: supply run rightward on top, consumer descending the far side between its isolating
  valves, return run leftward below, bypass closing the near vertical. Parallel branches repeat the U
  side by side off shared rails.
- **Symbol orientation conventions and the corner rule added.** An exchanger and a tank are vertical, a
  pump horizontal; an oriented component never sits at a two-run bend. A *junction* is not a bend — a
  three-way valve belongs at its T, because it is the junction.
